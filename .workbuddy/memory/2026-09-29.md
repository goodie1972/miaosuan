## 修复代理配置链：Dukascopy 在应用中无法获取数据

### 根因
Dukascopy fetcher 代码支持 proxy 参数，但**配置链中完全没有代理传递路径**：
- `settings.yaml` 无 proxy 字段
- `DataAcquisitionConfig` 无 proxy 字段
- `all_network_sources()` 不传 proxy 参数
- `_build_default_sources()` 不传 proxy 参数
- `_try_fetch_full()` / `_try_fetch_incremental()` 预先检查 `is_available()`，而 Dukascopy 的 TCP 探测直连不走代理 → 误判不可用 → 跳过获取

### 修复（四环节打通）
1. **settings.yaml**：新增 `data.proxy: 'http://127.0.0.1:10808'`
2. **settings.py**：`DataConfig` 模型新增 `proxy` 字段 + `DEFAULT_SETTINGS` 新增 proxy 默认值 + ENV 映射 `MIAOSUAN_DATA_PROXY`
3. **config.py**：`DataAcquisitionConfig` 新增 `proxy` 字段 + 两个 return 路径（测试/生产）均传递 proxy
4. **fetchers/__init__.py**：`all_network_sources()` 和 `list_network_sources()` 新增 `proxy` 参数，构造 `DukascopyFetcher(proxy=proxy)`
5. **acquisition.py**：
   - `_build_default_sources()` 传递 `proxy=cfg.proxy or None`
   - `_try_fetch_full()` / `_try_fetch_incremental()` 移除 `is_available()` 预检查（代理可达但直连探测失败的源不应被跳过）

### 验证
- 全测试套件：**1056 passed / 3 skipped / 0 failed**（基线一致）
- DataAcquisition.fetch('XAUUSD', 'D1', source='Dukascopy') 成功，缓存到 `data\cache\XAUUSD_D1.parquet`
- 后端服务已重启加载新代码

## 修复 _try_fetch_full / _try_fetch_incremental 静默失败

### 根因
`acquisition.py` 的 `_try_fetch_full` 和 `_try_fetch_incremental` 方法使用 `except Exception: continue`
静默吞掉所有来源异常，导致用户完全无法知道为什么取数失败。这是项目已知的系统性弱点
（已三度踩坑：Dukascopy `except DataError: break`、acquisition.py 四处 `except Exception: pass/continue`、
OKX `fetch_full` 丢弃入参 symbol）。

### 修复
1. **_try_fetch_full**：收集每个来源的失败原因，全部失败后通过 `logging.warning` 记录完整错误信息
2. **_try_fetch_incremental**：同上，额外包含 `since_ts` 参数信息
3. **`fetch()` 最终错误**：已通过 `_raise_no_source` 在 NetworkSource 层透传 failures，
   但 `_try_fetch_*` 层也需有日志记录作为补充

### 验证
- 全测试套件：**1056 passed / 3 skipped / 0 failed**（基线一致）
- 文件名模式验证通过：`XAUUSD_D1_Dukascopy_test.parquet`（source + note 正确组合）
- Dukascopy D1 全量获取成功（7021 行，2006-10 → 2025-12）
- API 可达性验证：proxy `127.0.0.1:10808` 正常工作，2025 年数据可用，2026 年返回 400（预期行为）
