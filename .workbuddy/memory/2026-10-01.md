## 修复：设置页「保存配置」8 连挂 pydantic 校验错误

**事故现象**：保存配置报 `8 validation errors for Settings`，全部是
`input_value=None`（webui.port / shenji.port / shenji.timeout / mt4.port /
timeout / poll_wait / drain_wait / data.timeout——恰好是 saveConfig 里所有
parseInt/parseFloat 字段）。

**根因链**（两层防线都缺失）：

1. 输入框为空时（loadConfig 未返回就点保存 / 加载失败——HTML input 只有
   placeholder 没有 value），`parseInt("")` → NaN；
2. `JSON.stringify(NaN)` → **null**（JSON 规范不允许 NaN，JS 序列化降级）；
3. `ConfigUpdateRequest` 的 section 是 `dict[str, Any] | None`——
   `model_dump(exclude_none=True)` **只剔顶层 section，不递归 dict 内部**，
   None 穿透；
4. `_deep_update` 把 None 合进 yaml 镜像 → `Settings.model_validate` 对
   int/float 字段报错 → 400。字符串字段不报是因为 `""` 对 str 合法。

settings.yaml 本身干净（验证失败不写盘，未被污染）。

**修复（双保险）**：

- 前端 `index.html`：新增 `getNum(id)`——NaN → `undefined`，
  `JSON.stringify` 省略 undefined 键 → 空输入不发该字段，yaml 原值保留。
  saveConfig 全部 8 处 parseInt/parseFloat 替换。
- 后端 `server.py` `POST /api/config`：合并前递归 `_strip_none`——
  None = 「未提供」不覆盖 yaml 原值；剥空的 section 也丢弃（否则会写
  `mt4: {}`）。防御任何客户端，不只本前端。

**回归测试**：新增 `tests/test_config_endpoint.py`（5 个）：
事故 payload（全 null）→ 200 且 yaml 原值保留、正常更新生效、非法值仍 400
（防御不能过度）、空 section 视为未提供。测试用 fixture 把单例
`SettingsManager._config_path` monkeypatch 到 tmp_path，快照/复原 `_config`
避免污染同进程后续测试。

**验证**：全量 1021 passed / 3 skipped / 0 failed（1016 + 新增 5）；
node --check 前端 JS 通过（注意：PowerShell 5.1 Get-Content 默认 GBK 读
UTF-8 会破坏中文产生假语法错误，须用 `[System.IO.File]::ReadAllText` 指定
UTF8 提取）；端到端冒烟——事故 payload POST → 200，GET 回读配置完好
（8686/1783/23232/30 全部无损）。

## 诊断：前端保存报「Failed to fetch」

用户报告新的错误：`保存失败：Failed to fetch`——**与前面的 pydantic 校验错误不同**。

**关键区分**：
- 8 个校验错误 = 后端返回 422，请求已到达服务器
- `Failed to fetch` = 浏览器侧网络错误，请求根本没发出/服务器无响应

**根因**：后端进程已死，端口 8686 无监听。用 curl 探测证实：
```
curl http://127.0.0.1:8686/api/meta → Failed to connect (exit 7)
```

**处理**：用 `.venv\Scripts\python.exe -m miaosuan.cli ui --host 127.0.0.1 --port 8686`
重启后端，三接口全部 200，事故 payload POST 返回 `{"ok":true,...}`——
证明前面修的 8 个校验错误确实生效（不是碰巧，是真修好了）。

**教训**：`Failed to fetch` 出现时第一步永远是 `curl http://127.0.0.1:8686/api/meta`
探端口——能返回 JSON 才轮到排查前端 fetch 调用；返回不了就是后端进程没了。
后端进程与前端页面生命周期独立，关闭终端窗口/异常退出都会让端口释放。

## 纠错：Dukascopy 公开历史 API 不需要 token

我曾错误地声称拉取 Dukascopy 数据「需要 API Token」，**这是错的，已向用户纠正**。

**事实**：
- `jetta.dukascopy.com/v1/candles` 是**公开免登录**接口（项目内
  `fetchers/dukascopy.py` 文档早已写明「历史数据走公开接口、无需凭据」，
  `settings.yaml` 的 `dukascopy_user/password` 恒为空字符串、仅为未来实盘预留）。
- 昨天实际运行 `duk_fetch` 成功拉到 M30 528,485 / M15 764,957 / M5 1,705,729 根，
  失败率 <0.1%——若需要 token，全部请求会 401/403，不可能有数据。
- 全 `tools/` 目录 grep `token|Authorization|Bearer|apikey|password` → **0 命中**，
  `http_get` 只带 `User-Agent` 头（duk_fetch_app.py:274）。

**我为什么会说错**：我用 WebFetch 直连该 URL 得到笼统的 `fetch failed`，
误判为鉴权问题。实际是**我这边 WebFetch 工具的网络环境受限**，不是 Dukascopy
要 token。教训：工具层的 fetch 失败 ≠ 目标接口鉴权失败；HTTP 401/403 才是鉴权
失败，笼统 fetch failed 先怀疑本侧网络。

## 本机代理链路实测（duk 拉数据用）

**jetta.dukascopy.com 不可直连（超时），必须走代理。** 实测三条路径：

| 路径 | 端点 | 结果 |
|------|------|------|
| v2rayN HTTP | `http://127.0.0.1:10808` | ✅ 5/5 成功 2.3s，出口 IP 152.42.237.192 |
| Windows 系统代理（注册表） | `http://localhost:15236` | ✅ 可用（默认 opener 读注册表成功） |
| 会话注入 env `HTTPS_PROXY` | `http://127.0.0.1:58027` | ❌ **超时不可用**（WorkBuddy 注入的会话代理） |

**坑**：`duk_fetch_app.py` 未传 `--proxy` 时按 `HTTPS_PROXY` env → 58027 →
超时失败（main() 读 env 优先于系统代理）。**必须显式 `--proxy http://127.0.0.1:10808`**，
或在无 WorkBuddy env 的干净终端跑（此时 fallback 到注册表 15236 也可用）。
主项目 `settings.yaml` 的 `data.proxy` 已是 10808，一致。

## duk_fetch 重构：按年倒序分批 + 15 天重叠验证 + checkpoint v2

用户要求修复昨天拉取的「数据断裂」：改为从今天往前按年分批、批间保留 15 天
重叠区做叠加对比后再截断合并、恢复时必须先验证再继续。团队两轮实现+两轮 QA：

- **实现**（tools/duk_fetch_app.py，约 1300 行重写）：
  - build_batches：`[start,end)` 左闭右开；batch0=[当年-01-01, 明天)，老批 end=年轻批 start+overlap_days，尾批 [2006-10-05, 2007-01-16)；

  - checkpoint v2（version==2 才认，旧格式保留 final 从 batch0 重来，tmp+os.replace 原子写）；
  - merge：subset = stage[time<overlap_start] ∪ 重叠区 final 缺失行，concat(final 在前)
    →mergesort→keep='first'（final 优胜）；
  - CLI 新增 --overlap-days/--tol-price/--tol-mismatch-pct/--max-batches；
    退出码 0/1/2(验证失败)/3(final 损坏)。
- **QA 一轮审计揪出 3 缺陷并已修**：R3 高危（final 非原子写+损坏被当首拉→静默丢
  历史 → 改 tmp+os.replace + 读损坏抛 DataError 预检中止 exit 3）；R2（删 stage→写

  R1（批内游标只批末落盘 → advance_cursor 每节奏推进，先写 stage 后写 ckpt）。
