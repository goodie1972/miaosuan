## 方案 C 落地：fetch() 返回 FetchResult（消除「静默失败」核心坑源）

**背景**：Dukascopy 拉数"看似成功实则返回旧缓存"问题。此前已修 `_cache_path` 漏传
source_type 的 bug（显式指定源时文件名带 `_Dukascopy` 后缀）。本次按方案 C 重构
`fetch()` 契约，解决「所有源失败仍静默返回旧缓存」的假成功问题。

### 改动

1. **`src/miaosuan/data/acquisition.py`**（核心）：
   - 新增 `FetchStatus` 枚举：`UPDATED`（拉到新数据）/ `UP_TO_DATE`（源确认无新 bar）
     / `STALE_FALLBACK`（全失败回退旧缓存）——三态语义，`fresh: bool` 不够用的教训。
   - 新增 `FetchResult` dataclass：path/status/source_used/errors/warnings，
     实现 `__fspath__`（旧调用方 `pd.read_parquet(result)` 不破坏）+ `to_dict()`（JSON 友好）。
   - 新增内部 `_Attempt` dataclass：`df/failures/source/ok`——核心是 `ok` 字段，
     区分「源正常响应但空数据」(UP_TO_DATE) 与「所有源全挂」(STALE_FALLBACK)，
     这正是旧版把两种语义压成同一个 `None` 的缺陷。
   - `_try_fetch_full/_try_fetch_incremental` 返回 `_Attempt` 而非 `DataFrame | None`；
     新增 `_extract_failures()`：从下层 `DataError.context["failures"]` 提取结构化明细
     （NetworkSource 已收集，上层不再丢弃）。
   - `fetch()` 主流程：增量成功→UPDATED；增量 ok 且有缓存→UP_TO_DATE；增量失败→
     试全量；全量成功→UPDATED（增量失败降级为 warnings）；全量失败且有缓存→
     STALE_FALLBACK 携带 errors；无缓存→抛 DataError 且 `context["failures"]` 逐条在。
   - 新增 `_dedup()`（增量/全量两阶段同源可能报同样的错）。

2. **`src/miaosuan/webui/server.py`**：`/api/acquisition/fetch` 透传 `result.to_dict()`
   全部字段（status/errors/warnings/stale/source_used）。

3. **`src/miaosuan/webui/static/index.html`**：
   - 新增 `.modal-title.warn` 样式（var(--warn) 橙色）。
   - `startAcqFetch` 三色处理：updated/up_to_date=绿、stale_fallback=橙（列出各源失败原因），
   - warnings 非空时附「部分源异常（不影响结果）」明细。

4. **`tests/test_mt4_bridge.py`**：端到端测试改用 `res = acq.fetch(...)`，
   新增断言 `status is UPDATED` + `source_used == MT4`。

5. **`tests/test_fetch_result.py`**（新增，10 个测试）：ScriptedSource 可编排假源，
   覆盖三态全路径、部分源失败 warnings、failures 逐条透传、__fspath__ 兼容、
   to_dict JSON 友好、显式 source 文件名分离。坑：`df == "empty"` 返回 DataFrame
   放进 if 会抛歧义错误，必须先 isinstance。

## 追加模式：fetch(append_to=...) 把增量接到指定文件后（写入前强制连续性校验）

**用户需求**：本地缓存列表选一个文件，把新拉的增量直接接在该文件末尾；但
「添加前要确认数据是准确的、能连续下去」——接错数据比没数据更危险。

### 设计（两层校验，任何一条不过即拒绝且不写文件）

1. **文件名层**（纯路径解析，读盘前）：`infer_symbol_timeframe(target)` 的
   品种/周期 vs 请求——错配即抛 DataError。校验顺序：文件名 → 存在性 →
   parquet 格式 → 读盘（先报最具体的错，如 `nope.parquet` 报品种错配而非「不存在」）。
2. **数据层**（`_validate_continuity`，返回 `(problems, warns)`）：
   - 数据实际中位 bar 间隔 vs 请求周期，超 ±25% 拒绝（文件名对但内容是 D1 冒充 H1）；
   - 时间戳单位 s/ms 混用拒绝（注：毫秒多根会先被周期校验拦下，单根才走到这层）；
   - `new_max <= old_max` 拒绝（源没按 since 过滤，空转写盘）；
   - 缺口分级：> max(30天, 3×周期) 拒绝；> max(7天, 5×周期) 通过但进 warnings；
     更小静默通过。

### 追加模式行为边界

- 增量起点 = 目标文件 `max(time)`；**不走全量覆盖**（全量会整体替换目标文件，
  违背「接在后面」语义）——增量失败直接 STALE_FALLBACK，文件原样；
- 校验过但无净新增（全被去重吃掉）→ UP_TO_DATE 不写盘；
- 仅支持 .parquet；损坏文件报「文件可能损坏」可行动提示。

### 改动清单

- `acquisition.py`：`_TIMEFRAME_SECONDS` 周期映射 + 缺口/周期/容差常量；
  `fetch(append_to=...)` 分流到 `_fetch_append`；`_validate_append_name` /
  `_validate_continuity` 两个校验器；模块级 fetch 透传。
- `server.py`：`FetchRequest.append_to` 字段；`_resolve_data_file` 路径白名单
